Edge autofill crash: hidden native <select>

Minimal reproduction of a renderer crash (STATUS_ACCESS_VIOLATION) in Microsoft Edge 153 on Windows. The tab crashes when browser address autofill fills a form containing a visually hidden native <select> inside a CSS container query.

Before you start

Edge needs at least one saved address: edge://settings/personalinfo. Open a case below, click the first field, and hover or click an address suggestion.

  • Crashes 1. Plain HTML, hidden select No JavaScript and no libraries. A normal address form plus one visually hidden <select>.
  • Control 2. Plain HTML, no hidden select The same form with the hidden select removed.
  • Suspected 4. Hidden select inside a container query Case 1 plus container-type: inline-size on the form, which is what a Tailwind @container class does.
  • Control 3. Radix UI Select React plus @radix-ui/react-select, which renders that hidden <select> itself. Add ?container=1 for case 5: the same page with a container query on the form.

What we see

  • Cases 1, 2 and 3 fill the form normally in Edge 153. The hidden <select> alone is not enough to crash the tab.
  • Case 4 adds the container query, which is the difference from the site where the crash was first seen. Try it and cases 3 and 5 to see which combination crashes.
  • Chrome 153 is unaffected in all three cases.
Tested with Edge 153.0.4234.32 (64-bit) on Windows. Crash IDs are in edge://crashes.
